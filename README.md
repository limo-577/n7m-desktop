# 唱歌笔记 + N7m 播放器（桌面合并版）

这是把「唱歌笔记」（歌词标注工具）和「N7m」（本地音乐播放器）合并成的一个 Windows 桌面应用项目。
打开后顶部有两个页签：**📝 歌词标注** 和 **🎵 播放模式**，点击切换，两边的功能都是完整保留的原版功能，
没有互相覆盖或删减。

## 目录结构

```
singing-notes-desktop/
├── package.json      Electron 项目配置 / 打包配置
├── main.js           Electron 主进程入口
└── renderer/
    └── index.html    合并后的完整界面（歌词标注 + 播放器）
```

## 第一次使用：安装依赖

电脑上需要先装好 Node.js（你说已经装了，那这步应该没问题）。

1. 把这个项目文件夹解压到你电脑上任意位置，比如 `D:\singing-notes-desktop`
2. 打开命令行（Win+R 输入 `cmd` 回车，或者用 PowerShell / Windows Terminal 都行）
3. `cd` 进入这个文件夹，例如：
   ```
   cd D:\singing-notes-desktop
   ```
4. 安装依赖（只需要做一次，之后不用重复）：
   ```
   npm ci --ignore-scripts
   npm run install:electron
   ```
   这一步会花几分钟联网下载 Electron 本体，文件比较大（几百 MB），耐心等一下。

安全修复版使用上述两步安装：先按锁文件安装依赖并跳过第三方安装脚本，再通过项目专用命令下载 Electron。`install:electron` 和 `dist` 仅在各自 Node 进程中启用已修复的 npm undici 7.30.1，避免使用宿主 Node 内置的旧 fetch；不修改系统 Node、全局 NODE_OPTIONS 或桌面运行时。直接运行 `npm install` / `npm ci`（未带 `--ignore-scripts`）或直接调用依赖 CLI 会绕过这个项目保护流程。未来新增依赖若需要安装脚本，须单独核查后显式运行。

安全回归命令：`npm test`。编辑页面内联脚本后运行 `npm run update:csp` 再测试。最新审核结果见 `SECURITY_REVIEW_20261016.md`，其中列出了尚未决定的同 ID 导入覆盖策略与其他剩余风险。

源码仓库不提交生成的 FFmpeg 可执行文件和 DLL。全新检出后，运行 `npm start` 或 `npm run dist` 前，先按对应源码包内的 `README.md` 从 FFmpeg/LAME 源码构建并暂存运行时；暂存脚本会验证组件清单和哈希。当前工作目录已有本地构建产物，直接运行即可。

## 平时开发调试：直接运行（不用打包也能用）

```
npm start
```

运行前会校验项目内置的 FFmpeg 文件、版本、组件配置和 SHA-256；启动时不会下载 FFmpeg。之后会直接弹出一个像桌面软件一样的窗口，运行的就是 `renderer/index.html` 里的内容。以后我给你新版本，
只需要把新的 `renderer/index.html` 覆盖替换掉旧的，再 `npm start` 就能看到最新效果，不需要重新安装依赖。

FFmpeg 采用本地源码构建的 LGPL 配置，只启用 WAV demuxer、PCM S16LE decoder、MP3 muxer、LAME encoder 和 `file` 协议。通用媒体解码器、解析器、网络协议、设备输入输出、硬件加速、`ffprobe` 和 `ffplay` 均未编入。FFmpeg CLI 自动带入一小组内置滤镜；应用调用固定的音频参数，不接收用户提供的滤镜表达式。FFmpeg 与 LAME 动态链接。

对应源码包为 `dist/ffmpeg-8.1.3-wav-pcm-mp3-source-x64-windows-lgpl.zip`。其中含本次使用的 FFmpeg 与 LAME 源码归档、精确 overlay port 配方与补丁、依赖清单、构建说明及许可文本。公开发行时必须把该 ZIP 与安装程序放在同一下载页。本次未上传到外部站点。构建来源和组件清单见 `resources/ffmpeg/PROVENANCE.md`。

安全核对依据 FFmpeg 官方公告与当前发布分支信息。官方公告涉及的 DVB 字幕解析器、RSCC、Screenpresso、TIFF、MagicYUV 等解码组件，以及网络协议均未编入当前二进制。转码 IPC 仅使用应用生成的 WAV/PCM 文件和固定参数。正式公开发布建议由发行方使用 Authenticode 证书签名安装包。

## 正式打包成安装包（生成真正的 .exe 安装程序）

```
npm run dist
```

打包时 electron-builder 可能需要下载其 Windows 安装器工具；FFmpeg 已从项目目录读取并经 SHA-256 验证，不会联网拉取第三方预编译版本。
打包完成后，去项目文件夹里的 `dist` 目录找生成的安装包，文件名类似：

```
dist/唱歌笔记桌面版 Setup 1.0.0.exe
```

`npm run dist` 结束时会生成对应的 `.sha256` 文件；公开下载时建议和安装包一起提供，便于用户核对文件完整性。

双击这个安装包，跟安装普通软件一样，一路下一步，装完桌面会有图标，以后就双击图标打开，
不再需要命令行、不再需要 Node.js 环境，是一个完全独立的桌面程序。

## 关于数据保存

两边（歌词标注 / 播放器）各自的数据都是用浏览器的 localStorage 保存在这个应用自己的独立存储空间里，
跟你电脑上其他浏览器、其他网页完全隔离，不会互相干扰。因为现在是从一个固定的本地安装位置加载，
不再是"每次可能换个文件路径"的情况，存储会比之前用浏览器直接打开网页文件稳定很多。

## 本轮修复（找到并确认的真实 bug）

- **关键 bug**：打包配置里漏掉了 `preload.js`，导致打包后主程序和悬浮歌词窗口之间的通信桥完全没加载
  （这是你 Console 报错 `Unable to load preload script` 的直接原因）。这一个 bug 连带导致了：桌面歌词
  被困在软件窗口里、LRC/标注切换没反应、锁定按钮误触发悬浮窗重开等一连串问题。现已修复。
- 悬浮歌词窗口页面重写：之前只认旧的 `opacity`/`color` 两个字段，且没有背景板元素，导致歌词透明度、
  背景透明度、背景颜色调了都没用。现在歌词文字和背景板是两层独立元素，五个参数都能单独生效。
- 渐变预设会把整个播放器界面的文字颜色一起改掉（选"极光幻境"变成满屏白字看不见）：原因是预设写的是
  播放器全局文字颜色变量，现在改成了歌词专用的颜色变量，界面其它文字不再受影响。
- 播放按钮改回居中对称布局。
- 开发者工具不再自动弹出，改为按 F12 手动开关。
- 标注区新增小/中/大三档字号切换（歌词文字和上方/中间标注符号一起缩放），会记住选择。
- 音频文件夹功能改为桌面原生实现：选一次文件夹后路径永久保存，不再需要每次重新授权；打开歌曲时会
  自动在文件夹里按歌名匹配同名的音频**和 LRC 歌词**一起加载，不用来回手动导入。

## 关于联网

安装后的标注、播放、播放列表、外观设置和 PNG/PDF 导出都使用本地资源，可离线使用。以下情况会访问网络：

- 页面使用系统字体，不会向第三方字体服务发起请求。
- 开发环境运行与打包时只校验项目内置 FFmpeg；发行安装包会把 FFmpeg 和 PNG/PDF 导出库一起打包。

公开发布时，必须把 `dist/ffmpeg-8.1.3-wav-pcm-mp3-source-x64-windows-lgpl.zip` 与安装程序一同托管，并在软件下载页直接链接到源码包和 LGPL 许可说明。本地源码包与安装包生成后仍须由发行方上传；当前工作区不执行外部发布。

## 两边功能保留说明

- **歌词标注区**：新建歌曲、逐字拆分、上方/中间/下方三种标注位置、连唱、停顿空格、自动标注换气、
  音频对照、音频文件夹自动匹配、预览导出 PNG/PDF、JSON 导入导出、深浅色模式——全部保留，和之前给你的网页版一致。
- **播放模式**：播放列表管理（拖拽排序）、逐字歌词高亮填色效果、外观自定义（背景渐变/纯色/图片、
  歌词颜色字号）、睡眠定时、拖拽导入音乐和 LRC——全部保留，和你原来那个播放器一致。

标注区右上角原来的「🎤 演唱模式」按钮改成了「🎵 播放模式」，点击后会直接切换到播放器页签
（用的就是你那个播放器的完整界面），不再是之前那个简化版的演唱模式。

## 这一版新增的两处能力

**1. 播放模式可以切换两种歌词来源**

歌词卡片标题下方多了一个小切换条：「LRC 歌词」/「标注歌词」。

- 「LRC 歌词」：就是播放器原本的能力，读取你给这首歌关联的 LRC 文件，逐字填色高亮。
- 「标注歌词」：会自动按**歌曲标题**去歌词标注区里找同名的歌曲，如果找到、并且那首歌是通过
  「导入LRC歌词」建立的（也就是每一行都有准确的时间戳），就会把你在标注区标好的全部内容
  （上方标注、中间标注、连唱下划线、下方备注）搬到播放器里显示，并跟着播放进度整行高亮。
  如果没找到匹配的标注歌曲，或者那首歌没有时间戳，这个选项会自动变灰不可选，并停留在 LRC 模式。

两边数据完全只读打通，播放模式看到的标注内容不会反过来修改标注区的数据，也不会影响播放器自己的
LRC 数据，互不干扰。

**2. 真正的桌面悬浮歌词**

之前那个"桌面歌词"其实是关在软件窗口里的一个浮层，离开窗口就看不到了。现在换成了 Electron
原生的**独立系统窗口**：无边框、透明背景、始终置顶，你可以把它拖到屏幕任意位置，切换到其他软件
（比如打游戏、看视频、用其他窗口）时它依然浮在最上层，跟 QQ 音乐、网易云那种真正的桌面歌词效果一致。
字体大小、透明度、颜色这些设置跟以前一样在「背景与颜色」面板里调，会实时同步过去。
窗口右上角有个隐藏的小 ✕，鼠标移上去才会出现，点一下关闭悬浮窗。

（这个功能依赖 Electron 的原生窗口能力，只有打包/运行成桌面应用后才有效，如果你哪天单独把
`renderer/index.html` 丢进普通浏览器打开，会自动退回到旧的、关在窗口里的浮层版本，不会报错。）
