风险与利用条件

  • DEP-01：旧通用 FFmpeg 只有在攻击者控制的媒体进入对应 demuxer/decoder 时才可能触发原生漏洞；旧包已替换。
  • DEP-02 至 DEP-05：分别需要 crafted WTV/DVB subtitle、RSCC、Screenpresso 或 TIFF 数据进入受影响 parser/decoder；这些组件未编入当前二进制。
  • CODE-01：损坏录音导致转码失败时，旧错误可能把 FFmpeg stderr 或临时文件路径带回渲染层；现仅返回通用失败提示。
  • CODE-02：旧远程字体请求会让第三方字体服务收到访问方网络元数据；请求已移除，页面资源限于本地。
  • CODE-03：若导入的歌词、曲名或标注未转义便插入 innerHTML，内容可能成为脚本；动态文本统一转义。
  • DEP-06/DEP-07：旧 html2canvas 仅残留在 jsPDF 可选安装树中，不进入发行 ASAR；后续可评估从安装树彻底去除。

已修复问题与风险条件

依赖和原生组件

旧 FFmpeg 风险：原 ffmpeg-static 5.3.0 携带通用 FFmpeg 6.1.1。只有当用户可控媒体进入相应格式/解码路径时，旧原生漏洞才可能被触发。本构建替换为本地源码构建的 8.1.3，并把组件限制到 WAV/PCM→MP3。

四项 FFmpeg 公告：对应漏洞分别要求 DVB subtitle parser、RSCC、Screenpresso 或 TIFF decoder 处理精心构造的媒体。构建时关闭 parser 和所有 decoder 后，仅启用 pcm_s16le；其余受影响模块未编入最终二进制。

支持组件：WAV demuxer、PCM S16LE decoder、MP3 muxer、libmp3lame encoder 和 file 协议。ffplay、ffprobe、网络、设备及硬件加速关闭。CLI 自动包含 16 个小型滤镜，名字记录于 BUILD_INFO；应用使用固定参数且不接收滤镜字符串。

代码、Electron 和数据边界

  • 录音 IPC 检查 PCM WAV 头、声道数、采样率、样本宽度、数据长度和 256 MiB 上限；并发转码拒绝，FFmpeg 进程 120 秒超时。恶意或损坏 WAV 只能进入 WAV parser，当前无远程上传入口。
  • FFmpeg 通过 execFile 调用固定可执行文件与参数，不经过 shell；只允许 file 协议。失败时不把 stderr、临时目录和本地路径传回 renderer。
  • 主/浮动窗口启用沙箱和上下文隔离，禁用 Node integration；导航、重定向、window.open 和 webview 受到限制；IPC 校验发送窗口与 frame。
  • 音频/LRC 真实路径限制在用户选择的目录下，并校验扩展名和体积。歌词、曲名和标注值进入 HTML 前转义；其他页面文本使用 textContent。
  • 移除了外部字体下载；页面 CSP 仅允许本地脚本、样式、媒体与资源。

源码、许可证与发布完整性

精确源码归档、LAME 源码、vcpkg overlay、应用补丁、许可证、SPDX、精确修订和构建说明均放入对应源码 ZIP。当前 ZIP SHA-512 清单和 ZIP CRC 检查通过。新暂存脚本支持显式应用路径、vcpkg 路径与 overlay 路径。每次 npm run dist 后会自动生成安装器 SHA-256 旁文件。

密钥与凭据

检查了源码、配置、文档、lockfile、发行元数据和最终 ASAR 文本，没有发现 API Key、Token、密码、私钥、Webhook 或云访问凭据。未发现已跟踪的 .env 文件；.gitignore 忽略 .env 与 .env.*，保留 .env.example 例外。没有需要配置的应用密钥，因此未创建空的 .env.example。

提醒：如果凭据曾经提交或泄露到外部平台，必须到对应平台作废并重新生成；只删代码不够。
